# azooKey Medical

azooKey Medical は、オープンソースの日本語入力 azooKey（Mac 版）をもとにした派生版です。医療の文章を打ちやすくするために、医療用語の辞書と、前後の文章を手がかりにした変換を足しています。変換はすべて Mac の中で行い、ネットには出ません。

> **注意**　個人が作った非公式の試作（アルファ版）で、本家の azooKey とは関係がありません。不具合はこのリポジトリに書いてください。医療用語の変換は誤ることがあります。診療録など正式な記録では、確定した文字を必ず読み直してください。医療機器ではありません。

## 元の azooKey との違い

- **医療用語の辞書**を同梱しました。元データは JMED-DICT mini（奈良先端科学技術大学院大学、CC BY 4.0）で、配布版には約20万語が入っています。元の辞書では候補にも出てこない語だけを足しています。「気管／器官」「大体／大腿」のような同音の語のどれにするかは、前の文章を見て変換AIが決めます。
- **ローマ字で打った英単語を、その部分だけ英字のまま残します。** 日本語入力のまま `kinoucomputerwotukatta` と打つと、入力中の文字は「きのうcomputerをつかった」になり、変換すると「昨日computerを使った」になります。かなに変われない文字（computer の m など）があるときだけ、その前後で英単語を探すので、`tenki` のようにかなになる綴りは今までどおりかなになります。英単語かどうかは macOS の英語の綴りの辞書で調べます（Mac の中で調べ、外には送りません）。CT・MRI・CRP など、よく使う医療の略語は、小文字で打っても大文字で出ます。設定の「ローマ字で打った英単語を自動で英字にする」で切れます（最初は ON）。
- **配布用の zip の変換AIは、医療の文章で追加学習したモデルです**（[下の節](#配布用の-zip-の変換ai)）。ソースからビルドしたときは、元の azooKey と同じ zenz-v3.2-small です。
- **前の行も変換の手がかりに使います。** 元の azooKey が使うのは、カーソルと同じ行の30文字だけです。
- **打った文章を入力欄ごとに覚えます。** Notion や Chrome のように、入力ソフトへ前の文章を渡さないアプリでも、自分が打った文章を手がかりに変換します。覚えるのはメモリの中の直近100文字だけで、ファイルには保存しません。入力欄を離れたとき、3分打たなかったとき、矢印キーや ⌘・⌃ を使う操作をしたときに消します。英数モードで打った文字と、パスワードの欄で打った文字は覚えません。
- **ノートのタイトルとカーソルの後ろの文章**も、変換の手がかりに渡します（実験的）。タイトルは変換AIの「話題」の欄に、後ろの文章（同じ行の20文字まで）は変換AIの「後ろの文脈」の欄に入れます。日付や「メモ」のような中身のないタイトルは渡しません。
- **範囲選択して Option + Return を押すと**、選んだ文を AI への指示として実行し、結果に置き換えます。範囲を選んでいないときは、キーをそのままアプリに渡します。キーは設定画面で変えられ、機能ごと切ることもできます。Control + Return は macOS 15 から OS が右クリックメニューを出すのに使っていて、入力ソフトには届かないので使えません。AI は、Mac に入っている Apple Intelligence か、この Mac の中で動かす LLM（Ollama など）から選べます。選んだ文の前後200文字も参考として渡し、アプリが前の文章を返さないとき（Notion や Chrome など）は、打った文章の記憶で補います。
- Option + Return を別の機能に使うアプリ（Excel や Numbers のセル内の改行、JetBrains の IDE など）で、範囲を選んで押すと AI が動きます。困るときはキーを変えるか、機能を切ってください。
- 元の azooKey にある「何も選んでいないときに ⌃S で続きの文の候補を AI に出させる」機能は、最初は OFF です。この版は AI を最初から使うので、元の azooKey と同じく ⌃S をアプリに渡すようにしました。
- 打った文章を外部に送りません。ネット通信の権限は、この Mac の中の LLM に接続するためだけに使い、接続先が 127.0.0.1・localhost・::1 のとき以外は送る前に断ります。転送（リダイレクト）にも従いません。そのため OpenAI などの外部の AI は使えません。画面の文章を集める別アプリ Tuner との連携も外しています。

## Mac の中に残るもの・外に出るもの

- **外に出るもの:** IME からは何も送りません。ただし Ollama には、ollama.com で動く「クラウドのモデル」（名前が cloud で終わるもの）があり、これを頼むと Ollama が文章を ollama.com へ送ります。IME はこのモデルを一覧に出さず、頼まれても送りません。Ollama の側でもクラウドの機能を切っておくと安心です。`~/.ollama/server.json` に `{"disable_ollama_cloud": true}` と書いて Ollama を再起動し（`brew services restart ollama`）、Ollama のログに `Ollama cloud disabled: true` と出ることを確かめてください。
- **Apple Intelligence を選んだとき:** Mac の中の Apple のモデルで処理します。
- **Mac の中に保存されるもの:** azooKey の学習データ（変換の履歴）、いい感じ変換で打った指示の履歴（最近の10件）、ユーザ辞書、変換プロフィールです。どれも暗号化せずに保存され、Time Machine にも入ります。学習は設定の「履歴学習」で止められ、「リセット」で消せます。
- **クリップボード:** AI の結果で置き換えられなかったときは、結果をクリップボードに入れます。ほかの Apple 機器には送らず、クリップボードの履歴を残すアプリにも残さないよう印を付けています。
- **ほかのプログラムからの差し替え:** この IME は自分のホームフォルダ（`~/Library/Input Methods`）に入れるので、同じユーザーで動くほかのプログラムが IME の中身を差し替えることを防げません。また、Ollama が止まっているあいだに、ほかのプログラムが同じ番号（11434）で待ち受けると、IME はそれを Ollama と区別できません。共用の Mac では注意してください。患者さんの情報を含む文章では、Mac の中の Apple のモデルで処理する Apple Intelligence がいちばん安全です。

## 評価

問題はどれも作者が作ったもので、数は少なめです。答えが1位に出た問題の数を数えています。この節の数は、変換AIのモデルが元の zenz-v3.2-small のときのものです。配布用の zip の追加学習したモデルの数は、[次の節](#配布用の-zip-の変換ai)にあります。

| 問題 | 辞書なし | 配布版の辞書あり |
|---|---|---|
| 医療用語 105問（病名・手術・解剖・薬・症状・検査・カルテ風の文） | 84 | 88 |
| 同音異義語 57問（前の文章つき） | 54 | 54 |
| 一般の文 30問 | 28 | 28 |
| 同じ読みを医療の文脈と普段の文脈で出す 38問 | 32 | 32 |
| 同じ読みの問題を新しく作り足した 20問（辞書なしでも全問正しいので、悪くならないことの確認だけ） | 20 | 20 |
| 医療の文脈で普段の語が正解になる 20問 | 19 | 19 |

この数字は割り引いて読んでください。辞書の作り方（どの語を入れるか、どれだけ効かせるか）は、これらの問題の結果を見ながら決めたので、初めて見る文章ではこれより下がる見込みです。また、問題の数が少ないため、105問の 84→88 は偶然の差と区別できません。

前の文章の効果も測りました。同音異義語57問の正答率は、辞書だけで変換すると58%、変換AIだけだと77%、変換AIに前の文章を渡すと95%でした。前の行に手がかりがある20問では、同じ行だけを使うと55%、前の行も使うと85%でした。

辞書を常に強く効かせると、「話の内容はだいたい」が「大腿」になるなど、普段の文章が崩れました。医療の文脈のときだけ強める切り替えは、実験的な設定として残してあり、最初は OFF です。

## 配布用の zip の変換AI

Releases で配る zip には、変換AIのモデルとして、元の azooKey の zenz-v3.2-small に医療の文章で追加学習したモデルを入れています。同じファイル（`zenz-v3.2-small-medical-P2g30-a050-Q5_K_M.gguf`）を Releases に単独でも置いています。ライセンスは CC BY-SA 4.0 です。学習に使った一般の文に、CC BY-SA 4.0 の Wikipedia 日本語版に由来する部分が含まれるためです。出典の表示は [NOTICE.md](NOTICE.md#配布用の-zip-の変換aiのモデル) にあります。

作り方の要点:

- 文章は、厚生労働省が公開している文書（重篤副作用疾患別対応マニュアル、指定難病の概要と診断基準、医師国家試験の問題）、科研費の研究課題の概要のうち医療の課題、一般の文（azooKey の作者が公開している zenz-v2.5-dataset の一部）を使いました。短く切り分けて読みを付け、変換の例を48万組作りました。
- 医療の語の読みは、配布版の辞書と同じく、JMED-DICT mini のうち万病辞書か百薬辞書を出典に含む語から付けました。変換エンジンは辞書の語を「辞書:語(よみ)」の形で変換AIに渡すので、学習の例の一部にも、配布版の辞書の語をこの形で付けました。
- 医療の語と読みが同じ普段の語（副腎と福神、血栓と決戦 など）を含む文の例も足し、普段の文が医療の語に変わりにくいようにしました。
- 学習は LoRA（元の重みは変えずに、差分だけを小さな行列で学習するやり方）で1周だけ行いました。学習で変わった分を半分の倍率で元の重みに足し、元のモデルと同じ Q5_K_M の形式にしました。
- 評価に使った文書は、学習に使っていません。

評価（配布版の辞書を入れた状態で、答えが1位に出た問題の数）:

| 問題 | 元のモデル | 追加学習したモデル | 元は正解で誤りになった / 元は誤りで正解になった |
|---|---|---|---|
| このリポジトリの問題 302問（`medical/eval` の8種類） | 264 | 281 | 1 / 18 |
| AJIMEE-Bench 200問（azooKey の作者が公開している日本語入力の評価用の問題） | 170 | 172 | 1 / 3 |
| 医療の文章 400問（学習に使わなかった厚生労働省と科研費の文書から作った問題） | 245 | 318 | 1 / 74 |

302問と医療の文章400問の差は、偶然の差とは考えにくい大きさです（McNemar 検定で p < 0.001）。AJIMEE-Bench の差は、偶然の差と区別できません。医療の文章400問は、学習に使った文書と同じ種類の文書から作ったので、ほかの医療の文章ではこれより下がる見込みです。普段の文で悪くなった問題もあります（AJIMEE-Bench で「ヨウ化銀」が「八日銀」になった1問）。医療の文章400問と学習データは公開していません。

ソースからビルドすると、変換AIのモデルは元の zenz-v3.2-small のままです。追加学習したモデルを使うときは、Releases から gguf を取得し、ビルドして入れるときに `ZENZ_GGUF=<gguf のパス>` を付けます（[入れ方](#入れ方)の3）。

## AI への指示（Option + Return）に使う AI

設定の「AI（選んだ文の実行・いい感じ変換）」の「使う AI」で選びます。

| 選択肢 | 準備 | 向いていること |
|---|---|---|
| Apple Intelligence（Mac の中） | 不要（Apple Intelligence を ON にしておく） | すぐ返ってくる短い書き直し |
| ローカルLLM（この Mac の中のサーバー） | Ollama などを入れてモデルを取得する | メールの文面、簡単な質疑応答 |

ローカルLLM の準備（Ollama の場合）:

```bash
brew install ollama
brew services start ollama          # ログイン時に自動で起動する。接続を受け付けるのはこの Mac の中だけ
```

Ollama は 0.17.1 以降を使ってください（それより前の版には CVE-2026-7482 という深刻な脆弱性があります）。Ollama を 0.0.0.0 で待ち受ける設定にはしないでください。

モデルは設定画面の「モデルを入れる（Ollama）」から入れられます。Gemma 4（E2B・E4B・12B・26B A4B・31B）と Qwen 3.5（4B・9B）を、ダウンロードの大きさとメモリの目安を添えて並べています。「入れる」を押すと Ollama がダウンロードし、終わるとそのモデルを使います。試していないモデルには「未評価」と出ます。ターミナルで `ollama pull <モデル名>` を実行して入れても同じです。一覧にないモデルは、モデル名の欄に名前を書けば使えます。

設定画面の「モデル」の欄には、この Mac に入っているモデルの一覧が出ます。おすすめのモデルも、Mac のメモリの大きさに合わせて表示します。使わずに5分たつとモデルはメモリから外れ、次の1回は読み込みに数十秒かかります。

AI が答えるまでの間は、選んだ文の下に、回る印と経過した秒数を出します。モデルを読み込んでいる間は「読み込んでいます」と出ます。Esc を押すと止められ、2分たっても返事がなければ打ち切ります。どちらの場合も元の文はそのまま残ります。

どの AI も医療の内容を誤ることがあります。返ってきた文は必ず読み直してください。

## 必要なもの

- Apple Silicon の Mac と macOS 26（作者は macOS 26.5 で確認しました。元の azooKey の作者は macOS 15 で確認しています）
- ソースからビルドするときは、Xcode 26.1 以上と Git LFS（`brew install git-lfs` のあと `git lfs install`）。医療用語の辞書も作るときは、Python 3 と Sudachi（`sudachipy` と `sudachidict_core`）も要ります
- AI への指示を使うには、Apple Intelligence を ON にするか、ローカルLLM（Ollama など）を入れておく必要があります

## 入れ方

Releases の zip を使うと、ビルドせずに入れられます。zip と、SHA-256 の値を書いた `.zip.sha256` のファイルを同じフォルダに落とします。ターミナルでそのフォルダに移り、`shasum -a 256 -c azooKey-Medical-*.zip.sha256` を実行して「OK」と出ることを確かめます。zip を開いてできたフォルダの中の `install.command` を、ターミナルで `bash <そのフォルダ>/install.command` として実行したら、下の4（入力ソースの追加）に進みます。この zip の変換AIは、追加学習したモデルです（[配布用の zip の変換AI](#配布用の-zip-の変換ai)）。

ソースからビルドするときは、次のとおりです。

1. 取得する

   ```bash
   git clone --recursive https://github.com/yushiwada/azooKey-Medical.git
   cd azooKey-Medical
   ```

2. 医療用語の辞書を作る（省くと、辞書なしで入ります）

   ```bash
   bash medical/eval/setup_anco.sh                                        # 変換エンジンのコマンドを作る
   (cd medical/harness && swift build -c release --product dict-builder)  # 辞書の形式に変換する道具を作る
   python3 -m venv medical/build/sudachi && medical/build/sudachi/bin/pip install sudachipy sudachidict_core  # 辞書の手直しに使う Sudachi
   SUDACHI_PY="$PWD/medical/build/sudachi/bin/python" bash medical/dictionaries/build_all.sh  # 元データの取得から辞書まで（8並列で30分ほど）
   ```

   何も付けないと、配ってよい出典の語だけの辞書を作ります。すべての出典の語を入れる版（`PERSONAL=1`）は、再配布できない出典の語を含むので、自分の Mac の中だけで使ってください。

3. ビルドして入れる（sudo は要りません）

   ```bash
   bash medical/scripts/build_install.sh
   ```

   Apple Developer への登録は要りません。自分の Mac で動かすための署名（ad-hoc 署名）でビルドします。変換AIのモデルが Git LFS の取得前のままなら、ビルドの前に止まります。ビルドしたものの写しに辞書を入れて署名し直し、権限とモデルのファイルを確かめてから入れ替えます。前の版は `medical/build/old/` に移します。

   変換AIのモデルは、元の zenz-v3.2-small のままです。追加学習したモデルを使うときは、Releases から gguf を取得し、`ZENZ_GGUF=<gguf のパス> bash medical/scripts/build_install.sh` とします。

4. システム設定 → キーボード →「入力ソース」の「編集…」→「+」→ 日本語 →「azooKey Medical (日本語)」を追加します。macOS 26 では、他社製の入力ソースをプログラムから有効にしても残らないため、ここだけは手で操作します。一覧に出ないときは、一度ログアウトしてから追加してください。

5. Caps Lock キーで日本語と英字を切り替えたいときは、同じ「入力ソース」の画面で、Caps Lock キーで入力モードを切り替える項目をオンにします。azooKey Medical の日本語で Caps Lock を押すと azooKey Medical の英字に、もう一度押すと日本語に戻ります。入れる前から開いていたアプリでは、そのアプリを開き直すかログアウトするまで切り替わらないことがあります。

ほかの Mac に配るときは、`medical` ブランチを変更のない状態で取り出し、`UNIVERSAL=1 bash medical/scripts/make_dist.sh` で zip を作ります（Apple Silicon と Intel の両方で動く版）。この版は、公開用の識別名と配ってよい辞書が入っていて、ホームフォルダのパスが中に残っていないときだけ作れます。zip の隣に SHA-256 の値を書いたファイルができるので、受け取った側は値を確かめてから、中の `install.command` をターミナルで実行します。`install.command` は、署名と CPU の種類を確かめてから入れ、前の版は `~/Library/Application Support/azooKey-Medical/old/` に移します。zip の中には、ライセンス文（`THIRD_PARTY_NOTICES.txt`）と辞書の出典（`DICTIONARY_SOURCES.txt`）も入ります。

Releases の zip は、`UNIVERSAL=1 ZENZ_GGUF=<追加学習したモデルの gguf> bash medical/scripts/make_dist.sh` で作りました。`ZENZ_GGUF` を付けると、変換AIのモデルを差し替え、zip の中の `BUILD_STAMP.txt` にモデルの名前と sha256 を書き、`THIRD_PARTY_NOTICES.txt` にそのモデルのライセンス文と出典の表示を入れます。公開用の zip には、`medical/licenses/23-zenz-v3.2-small-medical.txt` に sha256 を書いたモデルしか入れられません。

自分の別の Mac に、いま使っている版をそのまま移すときは `PERSONAL=1 bash medical/scripts/make_dist.sh` を使います。この zip は人に渡さないでください。

## 設定

入力メニューの「設定…」で切り替えられます。

| 設定 | 最初の状態 |
|---|---|
| ローマ字で打った英単語を自動で英字にする | ON |
| 前の行も文脈として使う | ON |
| 打った文章を覚えて文脈に使う | ON |
| ノートのタイトルも参考にする（実験的） | ON |
| カーソルの後ろの文章も参考にする（実験的） | ON |
| 医療用語の辞書を使う | ON |
| 医療の文脈では医療用語を強める（実験的） | OFF |
| 使う AI（AI の欄） | Apple Intelligence（使えない Mac ではオフ） |
| 範囲を選んでキーを押すと、選んだ文をAIへの指示として実行する | ON |
| 選んだ文を指示として実行するキー | Option + Return |
| 何も選んでいないときの ⌃S で、続きの文の候補をAIに出させる | OFF |

用語は「ユーザ辞書」の「編集」で1語ずつ登録できます。Mac のユーザ辞書（テキスト置換）に登録した語は「読み込む」で取り込めます。

## 医療用語の辞書の作り方

`medical/dictionaries/build_all.sh` が次の順に進めます。元データはリポジトリに含めず、作るたびに取得します。

1. JMED-DICT mini を版を固定して取得し、ファイルが配布元のものと同じかを sha256 の値すべてで確かめる（違えばファイルの名前を `.bad` に変えて止まる）
2. 読みと表記を取り出す（約46万語）。同じ語がいくつかのファイルにあるときは、出現回数の多い行を使う
3. 元の変換エンジンで、それぞれの読みが正しく変換されるかを確かめる
4. 正しく変換されない語だけを残す
5. 誤字を除く。JMED-DICT の表記は実際の医療文書から集めたもので、「前立線肥大症」のような誤字も含まれます。読みごとに、よく使われる表記だけを残します
6. 元の辞書で候補に出せる語と、語の断片（「ネフローゼ症候群」に対する「フローゼ症候群」など）を除く。自分が正規形の語は断片とみなさない
7. 普段の入力を乱す語を除く（`clean_entries.py`）。JMED-DICT の読みと表記は医療文書から機械的に集めたもので、読みの合わない組（「のうこう」に「脳震盪」など）や助詞の付いた語（「体を」など）が混ざっていて、普段の入力で1位に出てしまうことがあります。表記の1字ずつの読みをつないで読み全体を作れない組、よく使われる語の頭か尻尾が欠けた語、末尾か先頭に助詞が付いた語、動詞に助動詞が付いて終わる語を除きます。字の読みは、変換エンジンの辞書と Sudachi から取ります（漢方などで決まった読みのうち、どちらにもないものは `readings_extra.tsv` に置いています）。よく使う語と同じ短い読みのまれな語（「けっか」に対する「血痂」など）は、強く効かせる版（strong）だけから除きます。除いた語は、理由と一緒に作業フォルダの `dropped_entries.tsv` に書きます
8. 配布版（何も付けないとき）では、出典に万病辞書か百薬辞書（どちらも CC BY 4.0）を含む語だけにする。出典は読みと表記の組ごとに、誤字を除く前に確かめる。JMED-DICT の配布元は、再配布するときは元の各資料の権利を確かめるよう求めています
9. 変換エンジンの辞書の形式に変換する。辞書のフォルダには、出典の表示（`NOTICE.txt`）と作り方の記録（`BUILD_INFO`。入力したファイルの sha256 など）を置く

途中の確認の結果は、確かめた問題の sha256 と一緒に保存し、問題が同じときだけ使い回します。

辞書を作るのに要るものは次のとおりです。

- 変換エンジンのコマンド（CliTool。`medical/eval/setup_anco.sh` で作る）。3の確認と、7で変換エンジンの辞書から漢字1字と2字の語の読みを読み出す（`CliTool dict read`）のに使います。7で読む変換エンジンの辞書の場所は `AZK_DICT` で変えられます（既定は `setup_anco.sh` が取得したもの）
- 辞書の形式に変換する道具（dict-builder。`medical/harness` でビルドする）
- Sudachi（`sudachipy` と `sudachidict_core`）の入った Python。`SUDACHI_PY` で渡します（既定は `python3`）。作者は sudachipy 0.7.0 と SudachiDict core 20261015 で作りました。版が違うと、除く語が少し変わることがあります
- 7を飛ばして手直しの前の作り方で作るときは、`CLEAN=0` を付けます

自分用の語は `medical/dictionaries/personal/*.tsv`（1行に「読み」と「表記」をタブ区切り）に置くと、`PERSONAL=1` で辞書を作るときだけ一緒に入ります。配布版には入りません。

## 評価のやり直し方

```bash
bash medical/eval/setup_anco.sh
bash medical/eval/run_eval.sh medical/eval/medical_terms.json /tmp/result.json \
  --config_user_dictionary_dir medical/dictionaries/build/app_dictionary/weak
python3 medical/eval/summarize_eval.py medical/eval/medical_terms.json /tmp/result.json
```

辞書のフォルダは `weak` か `strong` まで指定します。指定したフォルダに辞書がないときと、変換AIのモデルがないときは止まります。変換エンジンの出力は `<結果>.json.log` に残ります。`medical/eval/eval_matrix.sh` を使うと、6つの問題をまとめて評価して表にできます。タイトルと後ろの文章を「話題」として渡す問題は、`medical/eval/make_topic_set.py` で評価用の形に直してから使います。IME と同じ処理で1打鍵ずつ確かめるには `medical/harness` の live-harness を使います（使い方は `medical/harness/run_live.sh`）。

## 分かっている限界

- 後ろの文章とタイトルは、前の文章ほどは効きません。
- 関係のない話題を渡すと、単独で打った医療用語の正答が下がることがあります。日付や「メモ」のようなタイトルを渡さないのはこのためです。
- 打った文章を覚える仕組みには、貼り付けた文章、ほかの入力ソフトで打った文章、マウスでのカーソル移動は分かりません。
- Option + Return で実行すると、選んだ文と前後200文字が AI に渡ります。前後の文章に指示のような文があると、AI がそれに引きずられることがあります。結果はそのまま選んだ文と置き換わるので、読み直してください（⌘Z で戻せます）。
- 「経尿道的膀胱腫瘍切除術」のように、辞書に入っていても長い語の途中で区切りを誤ることがあります。
- ローマ字で打った英単語のうち、`data` のようにかなに変われる綴りの語は、英字にならずに「だた」になります。英字にしたいときは、英字の入力に切り替えて打ってください。
- 英単語かどうかは macOS の英語の綴りの辞書で決めるので、辞書にない語（製品名など）は英字になりません。
- `meeting` のように、続きを待つ子音で終わる英単語は、打っているあいだは「めえちんg」のように見えます。変換するか Enter で確定するときに英字に直ります。
- 入力の途中でカーソルを動かしたり、文節の区切りを変えたり、一部を確定したりすると、その入力が終わるまで英単語を探すのをやめます。
- 作者の Mac で確かめた範囲の結果です。
